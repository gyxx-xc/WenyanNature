# 示例

## 最小输入示例

**用户输入**:
> 写一个 skill，当用户说"生成日报"时，读取今日 git log 并生成 markdown 日报。

**期望输出**:
- Skill 名: `daily-report`（全小写连字符）
- 触发关键词: "生成日报"
- 输出格式: Markdown 日报
- 执行步骤: 读取 git log → 解析 commits → 按类别分组 → 生成 MD
- 自由度: 中（提供模板，允许措辞调整）
- Gotchas: 不触发于"日报"等泛泛关键词，必须包含"生成日报"的明确意图

## 边缘情况示例

**用户输入**:
> 帮我写个 skill

**问题**: 过于模糊，无法确定功能、触发条件、输出格式。

**处理方式**:
1. 询问用户 Skill 的具体功能："你想让这个 Skill 完成什么任务？"
2. 如果用户仍无法明确，按"中自由度"设计一个可扩展的骨架 Skill，包含数据输入→处理→输出三个通用阶段，并注释说明哪些部分可替换。

**期望输出**: 一个通用的"command-runner"骨架 SKILL.md，包含 `inputs: []`、`steps: []`、`output: ""` 等占位字段，并在 description 中注明"需完善具体逻辑"。
